# Story 1.6: Per-agent multi-provider routing + conformance test

Status: done

## Story

As a user,
I want each agent to run on its own provider reliably,
so that a mixed-provider team actually works.

## Acceptance Criteria

1. **Given** a Team Package whose agents route to ≥2 different providers, **When** the Runtime starts a run, **Then** *before any LLM call is made* it resolves every agent's provider against the loaded Key Config and either proceeds (all usable) or aborts. Resolution uses the existing provider catalog's `is_usable()` / status data (`team_maker/adapters/providers/registry.py:16-23,64-66`) — **not** new hardcoded status strings, and **not** a second copy of the availability logic. (FR-10, AD-9)

2. **Given** one or more agents whose provider is unusable, **When** the pre-run check aborts, **Then** the error names **every** unusable provider (not just the first), and for each: the agent role(s) affected, the expected Key Config key name (the catalog's `env_var`, e.g. `ANTHROPIC_API_KEY`), and a plain-language fix — add that key to the Key Config, or add an `OPENROUTER_API_KEY` when the provider is `openrouter_reachable`. **No key value ever appears** in the message. (FR-10, FR-21, AD-9, NFR: keys never in output)

3. **Given** an agent routed to a keyless local provider (`ollama`, catalog `keyless_local=True`), **When** the pre-run check runs, **Then** it never blocks the run for that agent, with or without a Key Config. (FR-13)

4. **Given** an agent whose own provider key is absent but whose provider is `openrouter_reachable` and an `OPENROUTER_API_KEY` is present, **When** the run proceeds, **Then** that agent is **actually executed through OpenRouter** — an explicit OpenRouter-form model string and the OpenRouter key passed per-agent — not built with `api_key=None`. A gate that passes an agent as "usable via OpenRouter" and then hands the engine a credential-less LLM would fail mid-run, which is precisely the failure class AD-7 exists to prevent. (FR-22, AD-7, AD-8)

5. **Given** an agent whose `provider` value is not in the provider catalog at all (typo/unknown), **When** the pre-run check runs, **Then** the run aborts naming that provider as unrecognized — it does **not** silently degrade to `api_key=None` as it does today. (FR-10; closes a Story 1.5 review defer)

6. **Given** each agent's resolved credential, **When** the engine builds that agent's LLM and the crew executes, **Then** every LLM call carries that agent's own provider, model, and credential/endpoint, with **no cross-agent contamination** and **no reliance on process environment variables** — the run path never reads or writes `os.environ` for credentials. (FR-6, AD-7)

7. **Given** AD-7's mandate, **When** the test suite runs, **Then** a **multi-provider conformance test** exists that executes a real `crewai.Crew` for a team spanning ≥2 providers with the LLM call boundary intercepted, and asserts each agent's call was made with its intended provider/model/credential. It runs **offline** (no network, no real LLM spend) in the default suite, and it is documented as the gate that must pass before any CrewAI version change. (AD-7, spine "Deferred: CrewAI version pin")

8. **Given** the conformance test passes against the installed CrewAI, **When** `pyproject.toml` is updated, **Then** the `crewai` requirement is pinned to a bounded range covering the verified version instead of the current open-floor `crewai>=0.80.0`, with the conformance test named in a comment as the gate for widening it. (Spine "Deferred: CrewAI version pin"; closes a Story 1.5 review defer)

9. **Given** the `team-maker run` CLI, **When** a required provider key is missing, **Then** it prints the AC-2 message and exits `1` **before** any agent executes — no partial run, no traceback, no key value. (FR-10; CLI exit-code contract from Story 1.5 AC 6)

10. **Given** this story's scope, **When** implementing it, **Then** the run transcript (Story 1.7 / FR-27), new provider *adapters* behind `LLMProvider`, changes to the Factory (`pipeline/`, `generators/`, `validation/`, `artifacts/`), and changes to the generated `crewai_runner.py.j2` template are all explicitly **out of scope**. (AD-1; scope boundary)
